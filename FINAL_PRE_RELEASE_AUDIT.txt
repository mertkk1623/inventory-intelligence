1. EXECUTIVE SUMMARY
--------------------

Inventory Intelligence V1 is a single-SKU inventory and material planning workspace
built with Python and Streamlit. It reads one structured Excel workbook, validates it,
calculates stock and replenishment metrics, presents them across seven screens,
optionally explains them through an AI layer, and exports an Excel workbook and a PDF
report.

This audit re-ran every check against the shipped code rather than restating earlier
results. It reviewed all seven screens, both interface languages, the language-switching
path, the Excel contract, the calculation engine, the AI layer, both report formats, the
test suite, lint status, dependencies, configuration and repository hygiene.

Outcome: the product is portfolio-ready as a local pre-release build. Two
real defects were found and fixed during the audit, both specific to Streamlit 1.53 —
which is the minimum version declared in requirements.txt. A stale test count on the
Welcome screen was also corrected. No CRITICAL issue was found and no V1 behaviour was
removed or altered.

The audit found no evidence of a leaked credential, no personal absolute path in source,
and no generated binary committed to the tree. One factual caveat must accompany any
publication: the project is not a Git repository, so there is no commit history, no CI
run, and no remote to publish to. That is reported as a finding, not presented as a
completed step.

6. BILINGUAL COVERAGE
---------------------

Structure

  - One central module, utils/i18n.py, holds a 461-entry English→Turkish table.
  - Keys are the English source strings, and every English string is byte-identical to
    the literal it replaced. That is why 178 pre-existing English assertions kept
    passing after the language layer was introduced.
  - A missing key degrades to English instead of raising, so a newly added label cannot
    crash a screen.
  - Language is stored in st.session_state. One browser session cannot leak its language
    into another.

Coverage verified on every surface

Sidebar and brand, navigation labels, page titles, section headings, KPI labels, metric
descriptions, buttons, input labels, placeholders, help text, tooltips, validation
messages, warning and error banners, empty states, success messages, table headers,
chart titles, axis titles, legend entries, hover templates, annotations, report
descriptions, download button labels, AI disclaimers and AI loading messages.

Chart chrome was checked specifically because charts are where untranslated text usually
survives. Turkish output verified: Stok bakiyesi, Mevcut Stok, Birim, Güvenlik stoğu
100, Yeniden sipariş noktası 212, Günlük tüketim, Haftalık tüketim, Tüketilen birim, and
the hover template %{x|%d.%m.%Y}<br>Bakiye: %{y:,.0f} birim.

Untranslated-leak scan

A dedicated probe renders every Turkish screen and flags any visible fragment that still
equals a known English source string. Result: no untranslated leaks detected. The only
English strings that remain visible in Turkish mode are Excel sheet names and PDF
section names, which are deliberately kept in English so they match the file the user
downloads. That decision is disclosed in the Reports screen and in the README.

17. FINDINGS
------------

Priority definitions: CRITICAL blocks release; HIGH breaks a shipped feature or misleads
the user; MEDIUM degrades quality or completeness;
LOW is a contained defect or hygiene gap; SUGGESTION is optional.

CRITICAL

None. No release-blocking defect was found.

----------------------------------------------------------------------------------------

HIGH

F-1 — Navigation reset on every language change (Streamlit 1.53).
Streamlit 1.53 derives a radio widget's identity from its formatted option labels.
Because navigation labels are translated, switching language produced a new widget
identity and the selection fell back to the first option, silently returning the user to
Getting Started from any screen. Every analytics screen was affected, in both
directions.

Impact: a core bilingual feature appeared broken on the exact Streamlit version declared
as the project minimum.

Status: FIXED. The language handler now records the active page and re-applies it before
the navigation widget is created.

Evidence: check_switch.py passes on 1.53 and 1.67 — all six screens stay put.

Regression guard: test_language_switch_keeps_the_active_screen.

F-2 — Half-typed AI question discarded on language change (Streamlit 1.53).
The language handler called st.rerun(), which aborted the run before the question input
was re-created. Streamlit 1.53 then dropped the widget's state, so a user who typed a
question and then changed language lost the draft.

Impact: data loss in a normal workflow, on the minimum supported version.

Status: FIXED. The handler is now an on_change callback. Streamlit runs widget callbacks
before the script body, so the language applies in the same interaction with no rerun
and no lost state.

Evidence: check_widgets.py passes on both versions; the draft survives.

Behaviour note: the report date already survived; it was unaffected.

F-3 — Welcome status card showed a stale test count.
The card displayed 178 while the suite contained 190 tests.

Impact: a factual inaccuracy on the product's front door, in the one place a reviewer is
most likely to read it.

Status: FIXED — corrected to 190 in both languages.

----------------------------------------------------------------------------------------

MEDIUM

M-1 — Excel and PDF reports are English-only.
The interface is bilingual; the report files are not.

Assessment: inherent to the report build pipeline. Making reports follow the UI would be
a feature addition, which this audit was instructed not to make.

Status: MITIGATED, not removed. A scope note now appears on the Reports screen and in
both README halves. The English sheet and section names are kept visible on screen so
they match the file the user downloads.

M-2 — AI model output is English-only.
The prompt requests English prose, so responses are English even in Turkish mode.

Assessment: a deliberate prompt decision, and changing it would alter AI behaviour.

Status: MITIGATED. Disclosed on the AI Analyst screen and in both README halves.

M-3 — Lint configuration was not committed.
Ruff ran against an implicit, opinionated baseline, producing 60 findings and no
reproducible standard.

Status: FIXED. pyproject.toml now defines Ruff and pytest configuration explicitly.
Findings went 60 → 0.

M-4 — Runtime and development dependencies were mixed.
requirements.txt listed test and lint tooling alongside runtime packages, so anyone
deploying the app installed pytest and Ruff.

Status: FIXED. requirements.txt is now six runtime packages; requirements-dev.txt adds
pytest and Ruff and includes the runtime file.

----------------------------------------------------------------------------------------

LOW

L-1 — Download labels and table headers were untranslated.
Several button labels, table headers and numeric cells bypassed the translation layer.

Status: FIXED. Table headers now route through t(); numeric and date columns are
locale-formatted via localise_columns and table_date_format().

L-2 — Latent late-binding bug in localise_columns.
A loop closure captured the loop variable decimals late, so a formatting helper could
apply the wrong precision in a multi-column table. Lint rule B023 caught it.

Status: FIXED. Correct binding applied. This was a real defect, not a style complaint.

L-3 — zip() without strict=True in reports/pdf_theme.py.
Silent truncation would have occurred if the paired sequences ever differed in length.

Status: FIXED.

L-4 — .gitignore had gaps.
Several cache directories, editor folders, agent configuration and OS files were
uncovered.

Status: FIXED. Rewritten to cover .ruff_cache/, .mypy_cache/, opencode.json, .vscode/,
.idea/, .env.*, *.pem, *.key, *.tmp, *.bak, build/, dist/ and OS files.

L-5 — pytest.ini duplicated pyproject.toml.
Two sources of test configuration invite drift.

Status: FIXED. pytest.ini removed; configuration consolidated under
[tool.pytest.ini_options].

----------------------------------------------------------------------------------------

SUGGESTION

S-1 — Initialise a Git repository before publishing.
There is no version control today. git init, an initial commit and a .gitignore already
in place would make the project publishable and auditable. No history was created or
rewritten during this audit, by instruction.

S-2 — Add real screenshots.
The README contains none, deliberately: fabricating them was not acceptable. Real
captures of the seven screens, in both languages, would materially strengthen the
portfolio presentation.

S-3 — Let reports follow the interface language in a future version.
This would close M-1 properly. It is a V2-sized change, not an audit fix.

S-4 — Add a CI badge only after the repository is public.
The workflow file exists and is correctly configured, but it has never run, because
there is no repository to run it in. A badge before that would be inaccurate.

S-5 — Consider a dependency upper bound review at release.
pandas>=2.2,<4.0 and streamlit>=1.53,<2.0 are broad. Both were tested on current
releases, so this is a forward-looking note rather than a defect.
